## 한눈에 보는 결론

**서비스를 "혼자 쓰는 도구"에서 "여러 명이 동시에 쓰는 서비스"로 만들었습니다.**

핵심은 세 가지입니다.

| 무엇이 달라졌나 | 숫자로 |
|---|---|
| **동시 사용이 가능해졌다** | 동시 요청 2건 처리: 2.40초(직렬) → **1.21초(병렬)** |
| **데이터가 사라지지 않는다** | 업로드 실패 시 복구 불가 → **실패해도 기존 데이터 보존** |
| **안전망이 생겼다** | 테스트 337건 → **531건** (+194건) |

부수적으로 같은 질문에 AI를 다시 호출하지 않게 해 **토큰 비용 구조**를 개선했고, 리포트 숫자가 통째로 틀어질 수 있던 **회귀 2건을 배포 전에** 잡았습니다.

## 작업 1 — 동시성·데이터 안정성 (P0)

> **한 줄**: AI 작업 1건이 서버 전체를 멈추던 구조와, 업로드 실패 시 데이터가 영구히 사라질 수 있던 경로를 제거했습니다.

- **왜** — 당시 구조에서는 **동시 접속 2명이면 바로 드러나는** 문제가 있었습니다. CSV 분석·이미지 생성·AI 코멘트가 비동기 함수 안에서 동기(블로킹)로 실행돼, 한 사람의 작업이 끝날 때까지 다른 모든 요청과 진행률 표시까지 멈췄습니다. 또 성과 데이터 저장이 "기존 행 삭제 → 저장 → 복구 지점 생성" 순서여서, 저장이 실패하면 **한 달치 데이터가 복구 수단 없이 사라질 수 있었습니다.**
- **무엇을** — ① 블로킹 작업을 별도 실행 경로로 분리(19개 지점) ② 데이터 쓰기 순서를 "복구 지점 확보 → 삭제 → 저장"으로 역전 ③ 비밀번호 길이 검증을 가입·관리자 생성 경로까지 확대(기존엔 변경·재설정에만 있어 **1자리도 통과**) ④ AI 공급자 호출에 시간 한도·재시도 설정
- **언제** — 2026-11-16 (최우선 순위로 가장 먼저)
- **어디서** — 백엔드. 마케팅 업로드·미리보기·엑셀 내보내기·AI 코멘트, 이미지 편집/리사이즈/일괄변환, 헤딩 추천 경로 전반
- **어떻게** — 코드베이스에 **이미 올바르게 구현된 선례**가 있어 그 패턴으로 통일했습니다. 검증은 실제 앱에 동시 요청을 보내 측정했고, 같은 작업을 옛 방식으로 둔 대조군이 2.40초로 직렬화되는 것을 함께 확인해 측정이 유효함을 입증했습니다.

## 작업 2 — 조회 성능·대용량 처리·오류 응답 (P1)

> **한 줄**: 쓸수록 느려지는 구조를 걷어내고, 큰 파일을 우회 경로 없이 받을 수 있게 했습니다.

- **왜** — AI 기능의 월 예산 확인이 **호출마다 전체 사용 기록을 훑어서**, 로그가 쌓일수록 이미지 정제·헤딩 추천이 함께 느려졌습니다. 월별 조회도 날짜 인덱스를 타지 못해 매번 전체를 읽었습니다. 큰 엑셀은 응답 크기 제한에 부딪혀 **"메일로 받기" 우회 경로를 만들어야** 했고, 수천 행 키워드 비교는 필터·정렬할 때마다 멈췄습니다. 오류 화면에는 내부 메시지가 그대로 노출될 수 있었습니다.
- **무엇을** — ① 사용 기록·발송 기록에 인덱스 추가 ② 월별 조회를 인덱스를 타는 날짜 범위 조건으로 전환 ③ 파일 전송을 메모리에 담지 않고 흘려보내도록 변경 ④ 오류 응답 기준 정리 — **서버 탓은 사유를 로그에만**, 사용자가 고칠 수 있는 입력 오류는 사유를 그대로 ⑤ 표를 300행씩 나눠 그리기 ⑥ 조회 요청에 시간 한도, 긴 AI 작업에 **취소 버튼**
- **언제** — 2026-11-16 (P0 직후)
- **어디서** — 백엔드 DB 계층·전역 오류 처리 + 프론트 BFF 프록시·키워드 비교 화면·이미지 편집 화면
- **어떻게** — 로컬에 전체 스택을 띄워 확인했습니다. 10월 집계가 시드 데이터와 정확히 일치하고 인접 월이 섞이지 않음, 엑셀 516KB가 파일명·형식 그대로 전달됨, 500 응답이 내부 정보 없이 반환됨, 500행 업로드 시 300행만 그려지고 "더 보기"가 뜸을 모두 화면에서 검증했습니다.

## 작업 3 — 중복 제거·안전망 확보 (P2)

> **한 줄**: 같은 규칙이 여러 곳에 흩어져 **같은 입력에 기능마다 다른 결과**가 나오던 상태를 해소했습니다.

- **왜** — 투명한 이미지를 올리면 기능마다 결과가 달랐습니다. 특히 요소 분석에서는 투명한 부분이 **검게 깔려** 모델이 어두운 배경으로 잘못 읽을 수 있었습니다. AI 사용량 기록이 실패하면 사용자 요청 자체가 실패했는데, 그때는 **이미 토큰을 쓴 뒤**라 사용자는 실패한 줄 알고 다시 눌러 두 번 결제했습니다. 엑셀 리포트는 백엔드와 프론트 사이에 계약이 없어 한쪽이 바뀌면 화면에서 조용히 빈칸이 됐습니다.
- **무엇을** — ① 이미지 합성 규칙 4곳 → 1곳("투명한 곳은 흰색"으로 통일) ② AI 응답 해석 규칙 2곳 → 1곳 ③ 사용량 기록 5곳 → 창구 1곳(실패가 요청을 깨뜨리지 않게) ④ 화면 로직을 공용 훅 3개로 추출(업로드·비율 계산·끌어다 놓기) ⑤ 엑셀 리포트에 응답 계약 정의 ⑥ 메일 발송 경로를 관리자 전용·예산 게이트 적용으로 정리
- **언제** — 2026-11-16
- **어디서** — 백엔드 이미지·AI 공용 모듈 + 프론트 공용 훅 + 리포트 응답 계약
- **어떻게** — 가장 복잡한 **업로드 입구에 테스트 43건**을 붙였습니다(CSV 포맷·인코딩 감지, 매체별 컬럼명 변형, 기간 추출, 분류, 집계). 이 과정에서 파일명에 밑줄이나 한글이 앞에 오면 기간을 읽지 못하는 **실제 버그를 발견해 고쳤습니다.** 리포트 계약은 실제로 내보낸 516KB 엑셀을 다시 불러오는 왕복으로 확인했습니다.

## 작업 4 — 사후 교차검증 (P3)

> **한 줄**: 고친 코드를 다시 적대적으로 검증해, **고치는 과정에서 새로 들어간 회귀 2건**을 배포 전에 걷어냈습니다.

- **왜** — 앞선 세 작업에서 "**테스트는 통과하는데 버그가 있었다**"가 반복됐습니다. 테스트·타입 검사·빌드가 모두 통과한 상태에서도 잡히지 않는 종류였습니다. 그대로 두면 리포트 숫자가 통째로 틀어질 수 있었습니다.
- **무엇을** — 회귀 2건: ① **예산 상속 차단** — 관리자가 한 달의 예산을 비우면 그 달부터 **이후 모든 달의 예산이 0**이 됐습니다(예산소진율·잔여광고비가 전부 틀어짐) ② **날짜를 기간으로 오인** — `05.01~05.31` 같은 날짜 범위가 "2005년 1월"로 읽혀 빈 리포트가 생성됐습니다. 추가 리스크 4건: 되돌릴 수 없는 작업(메일 재발송·기간 삭제)이 시간 한도에 걸려 **실패로 보이지만 실제로는 수행**되어 메일이 두 번 나갈 수 있던 문제, 실행 스레드가 DB 연결 수보다 많던 불균형, 표의 행이 화면에서 사라질 수 있던 식별자 문제, 응답 압축 시 파일이 잘릴 수 있던 잠복 버그
- **언제** — 2026-11-16 (커밋 직후, 같은 날)
- **어디서** — 직전 변경분 전체(백엔드·프론트)
- **어떻게** — 변경분을 **다른 관점으로 다시 읽는** 교차검증을 돌렸습니다. 발견한 회귀는 고치기 전 코드로 되돌려 **테스트가 실제로 실패하는지 확인**한 뒤 수정했습니다. 예산 상속은 실제 API로 "11월을 비워도 12월이 10월 값을 상속"하는 것까지 검증했습니다.

## 작업 5 — 핵심 경로 테스트 공백 보강

> **한 줄**: 버그가 반복된 이유가 "테스트가 **없는** 곳이라 통과한 것"이어서, 기능의 중심부에 안전망을 깔았습니다.

- **왜** — 업로드·엑셀 저장·내보내기가 모두 올라가 있는 **작업 상태 저장소**에 테스트가 0건이었습니다. 화면이 3초마다 폴링하는 진행률, 취소 버튼, 1회용 다운로드, 자동 정리가 전부 여기서 결정됩니다. 이미지 리사이즈도 기능 전체가 함수 하나였고, 파일 저장 경로가 틀리면 저장은 되는데 나중에 못 찾습니다.
- **무엇을** — 테스트 **74건 추가** (432건 → 506건). "돌아가는지"가 아니라 **약속이 지켜지는지**를 고정했습니다 — 끝난 작업을 취소해도 결과가 "취소됨"으로 바뀌지 않을 것(완료는 사실), 결과 파일은 한 번만 받을 수 있을 것, AI 업스케일이 실패해도 리사이즈는 성공할 것, 잘린 응답과 형식이 다른 응답을 구분해 알릴 것
- **언제** — 2026-11-16
- **어디서** — 작업 상태 저장소, 이미지 리사이즈, 파일 스토리지 연동, AI 응답 해석
- **어떻게** — 네트워크·AI를 호출하지 않고 대역으로 대체해 외부 상태와 무관하게 같은 결과가 나오도록 했습니다. 테스트가 장식이 아닌지 보려고 **운영 코드를 일부러 되돌려** 확인했습니다 — 완료 상태 보호 장치를 빼자 4건, 저장 경로 규칙을 빼자 1건이 즉시 실패했습니다.

## 작업 6 — AI 코멘트 재사용 (토큰 비용 절감)

> **한 줄**: 같은 질문의 답을 두 번 사지 않도록 바꿔, 반복 호출 구조를 제거했습니다.

- **왜** — 코멘트는 같은 달을 반복해 묻는 구조였습니다. 대시보드의 "코멘트 업데이트", 관리자 **재발송**, **월간 자동 발송**이 모두 같은 기간을 대상으로 하는데, 실적이 하나도 바뀌지 않았어도 매번 AI를 호출했습니다. 받는 사람 입장에서도 같은 달 리포트의 문구가 발송할 때마다 달라져 어느 해석이 맞는지 혼란스러웠습니다.
- **무엇을** — 판정 기준을 **"AI에 보낸 질문 자체"**로 잡았습니다. 질문이 글자 하나까지 같으면 저장된 답을 그대로 씁니다. 데이터를 따로 비교하지 않은 이유는 이 기준 하나가 두 가지를 함께 해결하기 때문입니다 — **실적이 바뀌면 자동으로 다시 묻고, 질문 방식(프롬프트)을 개선해도 자동으로 다시 묻습니다**(개선한 질문이 낡은 답에 가려지지 않음). 재사용한 코멘트는 사용량 집계에 넣지 않아 **월 예산이 실제 사용량과 일치**하게 했고, 담당자가 엑셀에 직접 쓴 코멘트는 AI 산출물과 구분해 재사용하지 않습니다.
- **언제** — 2026-11-17
- **어디서** — AI 코멘트가 만들어지는 모든 경로(대시보드 버튼, 리포트 메일 재발송, 월간 자동 발송) + 대시보드 화면
- **어떻게** — 로컬 전체 스택에서 **AI 호출 횟수를 직접 세어** 확인했습니다. 요청 4회에 실제 호출은 2회(첫 생성 + 강제 재생성), 재사용 2회는 사용량 기록도 늘지 않았습니다. 행을 추가해 실적을 바꾸자 즉시 다시 호출됐고, 그 뒤로는 다시 재사용됐습니다. 문구를 바꿔 보고 싶을 때를 위해, **재사용했을 때만** 안내와 "새로 생성" 버튼이 나타나게 했습니다.

## IR 작성 시 쓸 수 있는 정리

### 숫자

| 지표 | 값 | 근거 |
|---|---|---|
| 동시 처리 성능 | 2.40초 → **1.21초** | 동시 요청 2건 실측, 대조군 비교로 유효성 확인 |
| 테스트 | 337건 → **531건** | 전 구간 통과 |
| 발견·수정한 결함 | **회귀 2건 + 리스크 10건** | 교차검증 2회 포함 |
| AI 호출 절감 | 요청 4회 → 호출 **2회** | 같은 달 반복 요청 시나리오 실측 |
| 변경 규모 | 파일 **70여 개**, 커밋 5건 | 기능 추가 아닌 기반 작업 |

### 메시지 후보

- **"동시 사용 가능한 서비스가 됐다"** — 데모·심사 환경에서 여러 명이 동시에 써도 서로를 막지 않습니다.
- **"데이터 신뢰성을 구조로 보장한다"** — 업로드가 실패해도 기존 성과 데이터가 남습니다. 데이터 신뢰성이 곧 제품 가치인 서비스에서 가장 치명적이던 리스크를 제거했습니다.
- **"고치고 나서 다시 검증하는 절차를 만들었다"** — 이번 작업의 결함은 전부 "변경분을 다른 관점으로 다시 읽는" 단계에서 나왔습니다. 테스트 통과가 끝이 아니라는 것을 확인하고, 그 단계를 작업 흐름에 넣었습니다.
- **"비용 구조를 손봤다"** — 같은 질문을 반복 구매하던 경로를 제거했습니다.
