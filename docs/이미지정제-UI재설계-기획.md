# 이미지 정제 화면 UI/UX 재설계 기획

> 대상 화면: `/image-filter` (사이드바 "크리에이티브 > 이미지 정제")
> 작성일: 2026-11-25
> 상태: **1~3단계 + 캔버스/버전레일 + localStorage 복구 완료, 실호출 검증 완료** (2026-11-26). 미구현 항목은 §8 참고.

---

## 0. 요약 (두괄식)

1. 지금 답답한 근본 원인은 모달이 없다는 점이 아니라, **편집 작업 전체가 화면 맨 아래 320px 서랍(`ComposerPanel`) 안에 들어 있다**는 점입니다.
2. 따라서 **① 화면 골격을 세로 스크롤형 채팅 → 가로 2열 작업대로 재구성**하고, **② 지시 작성·수정을 전용 모달로 분리**합니다.
3. 모달은 **밖 클릭 / Esc / X 모두 자동 저장**하며, 취소는 모달 내 `[되돌리기]` 버튼과 저장 직후 `실행취소` 토스트로만 제공합니다. **전송은 절대 자동으로 일어나지 않습니다.**
4. 함께 바로잡을 핵심 동작: **작성해 둔 지시가 전송 시 전부 함께 보내지는 현재 구조**를 `Instruction[]` + 체크박스 선택 전송으로 교체합니다.
5. 결과 표시는 **채팅 피드를 걷어내고 캔버스 + 버전 레일로 교체**합니다.

## 1. 현황 분석 — 왜 답답한가

분석 대상 파일:

| 파일 | 줄 수 | 역할 |
|---|---|---|
| `front/app/image-filter/ImageFilterClient.tsx` | 906 | 화면의 심장. 대화 피드·초안 관리·요소 분석·전송·배경 시안·objectURL 수명 관리 |
| `front/components/image-filter/AgentComposer.tsx` | 541 | 하단 sticky 입력 독. 첨부·요소 선택·출력 설정·배경 시안이 전부 여기 |
| `front/components/image-filter/ElementPicker.tsx` | 116 | 요소 bounding box 오버레이 |
| `front/types/imageFilter.ts` | 60 | `PromptDrafts`, `ALL_ELEMENTS_KEY`, `draftKeyOf` |
| `front/lib/imageFilterClient.ts` | 114 | API 4종 (analyze / edit / backgrounds / background-styles) |

### 1-1. 세로 공간을 두 번 빼앗긴 상태

| 요소 | 높이 |
|---|---|
| AppShell 공통 Header (`components/layout/AppShell.tsx`) | 약 56px |
| 페이지 자체 `<header>` ("이미지 정제" + 설명문, `ImageFilterClient.tsx:465`) | 약 68px |
| `min-h-screen` (`ImageFilterClient.tsx:451`) — AppShell `<main>` **안에서** 또 100vh 선언 | 최소 100vh |

AppShell이 이미 `min-h-screen flex`로 헤더를 올려 둔 상태인데 페이지가 또 `min-h-screen`을 요구합니다. 결과:

- 페이지에 **항상 스크롤이 생깁니다.**
- `sticky bottom-0`인 컴포저가 "뷰포트 하단"이 아니라 **"100vh+ 컬럼의 하단"** 에 붙습니다. 처음 들어온 사용자는 입력창을 보려고 스크롤부터 해야 합니다.

### 1-2. 가로 공간은 40%만 사용

사이드바에 256px(`lg:ml-64`)을 내준 상태에서 본문은 `max-w-3xl`(768px) 중앙 정렬입니다. 1920px 모니터에서 **1100px 이상이 빈 여백**입니다. 반대로 세로로는 모든 것이 쌓여 잘립니다.

### 1-3. 모든 작업이 하단 서랍 안에서 일어남 ← 사용자가 지적한 지점

`AgentComposer`의 `ComposerPanel`은 `max-h-80 overflow-y-auto`(320px 스크롤 박스)이고, 그 안에 들어가는 것이:

- **요소 선택** — 이미지 + bounding box N개 (`ElementPicker`)
- **출력 설정** — 가로/세로/비율 자물쇠/포맷
- **배경 시안** — 스타일 선택 + 생성

즉 **"320px 스크롤 박스 안의 썸네일 위에서 좌표 박스를 클릭"** 하는 구조입니다. 지시는 **`rows={1}`에서 최대 160px까지만 자라는 textarea**(`AgentComposer.tsx:112-117`)에 작성하며, 500자 제한인데 카운터는 `hidden sm:block`입니다.

### 1-4. 작성해 둔 지시가 보이지 않고, 수정·삭제 수단이 없음

`drafts`는 `Record<요소id, string>`(`types/imageFilter.ts:20`)입니다. 화면에 드러나는 단서는 두 개뿐입니다.

- 컴포저 위 11px 안내문 한 줄 — "작성해 둔 지시 3건(로고, 헤드라인 문구)을 함께 보냅니다" (`AgentComposer.tsx:357-364`)
- 요소 칩에 붙는 10px 연필 아이콘 (`ElementPicker.tsx:96-101`)

**특정 지시를 고치거나 지우려면 그 요소를 다시 선택해 textarea로 돌아가야 합니다.** 목록·수정·삭제 UI가 존재하지 않습니다.

### 1-5. 작성한 모든 지시가 무조건 함께 전송됨 (위험)

`ImageFilterClient.tsx:271-282`의 `pending`은 `drafts` 전체를 긁어 담습니다.

```
"로고 바꿔줘"를 써 두고 잊음
  → 나중에 "배경 흰색"만 보낼 생각으로 전송
  → 로고 지시까지 함께 전송됨
  → AI 호출 비용과 결과물이 예상과 다름
```

이를 알려주는 단서가 11px 안내문 한 줄입니다. UI 불편이 아니라 **사고 유발 동작**입니다.

### 1-6. 결과 이미지가 썸네일

`AgentBubble`의 결과 이미지는 `max-h-80`(320px)이고, 확대·원본 비교 수단이 없습니다(`ImageFilterClient.tsx:740-744`). 이미지 편집 도구의 결과물이 썸네일로만 제공됩니다.

### 1-7. 작업 중 전체 잠김

`busy = processing !== 'idle' || analyzing || bgLoading` (`ImageFilterClient.tsx:120`) 하나로 모든 입력이 잠깁니다. **"수십 초 걸릴 수 있어요"라고 안내하면서 그 수십 초 동안 지시 타이핑조차 막습니다.**

### 1-8. 새로고침하면 전부 소멸

`drafts`는 메모리 전용입니다. 영속화 선례는 있으나(`lib/reportStorage.ts` — IndexedDB + 쿼터 처리 + prune, `/dashboard`에서만 사용) 이 화면은 아무 저장도 하지 않습니다.

### 2-2. 핵심 변경 3가지

**① 뷰포트 고정 — 페이지 스크롤 제거**

`min-h-screen` → `h-[calc(100dvh - 헤더높이)]` + `overflow-hidden`. 좌·우 패널이 각각 내부 스크롤합니다. **이것만으로 체감 답답함의 대부분이 해소됩니다.**
`dvh` 사용 권장 — 모바일 주소창 높이 변화 대응.

**② 페이지 header → 1줄 툴바로 압축**

"이미지 정제 / 채팅하듯 지시하면 Gemini가 편집해 드려요" 설명문은 사이드바 메뉴 `description`에 이미 있으므로 제거합니다. 대신 **첨부 파일 칩과 출력 설정을 툴바로 끌어올려 상시 노출**합니다 — 현재는 "무엇을 어떤 크기로 뽑는지"를 전송 후 칩으로만 알 수 있습니다.

**③ 채팅 피드 → 캔버스 + 버전 레일 (확정)**

- 결과를 320px 버블이 아니라 캔버스 전체 크기로 표시합니다.
- 하단 썸네일 레일로 `원본 → v1 → v2` 를 넘나듭니다.
- `handleContinueFrom`(결과로 계속 편집, `ImageFilterClient.tsx:188-204`)은 현재 "어느 결과에서 갈라졌는지" 추적이 불가능한데, 레일이 그 계보를 그대로 드러냅니다.
- 배경 시안 N종은 같은 레벨의 분기로 묶어 표시합니다.
- 기존 `FeedItem`의 `kind: 'error' | 'notice'`는 버블 대신 **토스트 + 캔버스 상단 인라인 배너**로 이전합니다 (`ToastProvider`가 이미 전역에 있음).
- 각 버전에 "이 버전을 만든 지시"를 접이식으로 붙여 기록성을 보존합니다.

### 2-3. 반응형

| 폭 | 구성 |
|---|---|
| ≥1280px | 2열 (캔버스 `flex-1` + 패널 420px) |
| 768~1279px | 2열, 패널 340px로 축소. 출력 설정은 기본 접힘 |

## 3. 제안 B — 지시 편집 모달 + 자동저장

### 3-1. 진입점 3개

| 트리거 | 동작 |
|---|---|
| 캔버스에서 요소 박스 클릭 | 해당 요소의 지시 모달 (신규 또는 기존 수정) |
| 패널 카드의 **[수정]** | 해당 지시 모달 |
| **[+ 지시 추가]** | 대상 미지정 상태로 모달 |

추가 제안: **이미지 첨부 직후 자동 1회 오픈**. 가장 흔한 경로에서 클릭 수가 늘지 않습니다.

### 3-2. 모달 구성 (`Modal size="xl"`)

```
┌─ 🎯 지시 수정 — "헤드라인 문구" ─────────────────── [X] ┐
│                                                        │
│  ┌──────────────┐  대상  [ 헤드라인 문구        ▾ ]    │
│  │ 해당 박스만   │        ↑ 다른 요소 / 이미지 전체로   │
│  │ 크롭 확대 표시 │           바꿔치기 가능             │
│  └──────────────┘  위치  가로 12~45%, 세로 30~40%      │
│                                                        │
│  ┌────────────────────────────────────────────────┐    │
│  │ 이 문구를 "여름 시즌 최대 50% 세일" 로        │    │
│  │ 바꾸고, 글씨는 더 굵게 해줘.                  │    │
│  │               (min-h 220px · 자동 성장)        │    │
│  └────────────────────────────────────────────────┘    │
│                                        68 / 500        │
│                                                        │
│  💡 이런 지시가 많이 쓰여요  ← 요소 category 기반       │
│  [문구 교체] [글씨 굵게] [색상 변경] [삭제]            │
│                                                        │
├────────────────────────────────────────────────────────┤
│ [🗑 지시 삭제]  [↩ 되돌리기]        [저장] (Ctrl+Enter) │
└────────────────────────────────────────────────────────┘
```

**모달 안에 "전송" 버튼은 두지 않습니다.** 전송은 오른쪽 패널의 버튼 하나로만 가능합니다 — "자동 저장은 하되 전송은 절대 아니다"를 구조로 보장합니다.

### 3-3. 닫힘 동작 — 자동 저장 (확정)

| 행동 | 동작 |
|---|---|
| **모달 밖 클릭** | ✅ 저장 후 닫기 |
| **Esc** | ✅ 저장 후 닫기 (밖 클릭과 동일 — 확정) |
| **[X]** | ✅ 저장 후 닫기 |
| **[저장]** | ✅ 저장 후 닫기 |
| **[되돌리기]** | ↩️ 열었을 때 값으로 복원 후 닫기 ← **유일한 명시적 취소 수단** |
| AI 작업 중(`busy`) | 🔒 전부 잠금 (`Modal`의 기존 `busy` prop 그대로) |

**닫는 방법 3개(밖 클릭·Esc·X)가 모두 "저장"으로 일관**됩니다. Esc만 취소로 두면 "밖을 눌렀는지 Esc를 눌렀는지"를 사용자가 기억해야 하므로, 일반 관례보다 일관성을 택했습니다.

안전장치:
- 내용이 **실제로 바뀐 경우에만** 토스트 **"지시를 저장했어요 · [실행취소]"** (5초)
- 모달 하단에 상시 안내: "밖을 누르거나 Esc를 누르면 자동 저장됩니다"

### 3-4. 기존 컴포넌트로 거의 그대로 됩니다

`components/ui/Modal.tsx`(180줄)는 포커스 트랩·Esc·오버레이 클릭·`body` 스크롤 잠금·`busy` 잠금이 이미 전부 구현되어 있습니다. **`onClose`에 "저장하고 닫기"를 넣으면 컴포넌트 수정 없이 자동저장이 성립합니다.**

필요한 변경은 두 가지뿐입니다.

1. `size`에 `xl` 추가 — 현재 최대가 `lg`(`max-w-2xl`)로, 크롭 미리보기 + 220px textarea에는 좁습니다.
2. textarea를 DOM상 첫 focusable 요소로 배치 — 열면 즉시 타이핑됩니다. `Modal`의 포커스 로직은 그대로 둡니다 (`Modal.tsx:72-73`이 첫 `FOCUSABLE`을 잡음).

### 3-5. 한글 IME 안전장치 (놓치기 쉬운 지점)

저장 시 React state만 믿지 말고 `textareaRef.current.value`를 함께 읽어 **더 긴 쪽을 채택**합니다. 일부 IME에서 조합 미확정 글자가 밖 클릭 순간 유실될 수 있습니다.

**반대로 얻는 것**: 지시 작성이 모달의 큰 textarea로 옮겨지면 Enter = 줄바꿈이 정답이 됩니다. `AgentComposer.tsx:125-133`의 Safari 조합 확정 50ms 가드(`compositionEndedAtRef`) 같은 땜질 코드를 **삭제할 수 있습니다.**

## 4. 제안 C — 함께 손볼 시스템 항목

### C-1. 지시를 1급 객체로 — `PromptDrafts` → `Instruction[]` (확정)

| 현재 제약 | 근거 | 개선 후 |
|---|---|---|
| 작성한 모든 초안이 무조건 함께 전송 | `ImageFilterClient.tsx:271-282` | 체크박스(`enabled`)로 **일부만 전송** |
| 요소 하나에 지시 1건만 | 키가 요소 id | 한 요소에 여러 지시 가능 |
| 순서 제어 불가 | 객체 키 순서 의존 | 드래그로 `composeEditPrompt` 번호 순서 제어 |
| 전송 성공/실패 복구가 수동 | `:304-308`에서 비우고 `:338-344`에서 되살림 | `status`로 상태 추적 |

제안 형태:

```
Instruction {
  id,
  targetElementId: number | null,   // null = 이미지 전체
  text,
  enabled: boolean,                  // 전송 포함 여부
  status: 'draft' | 'sent' | 'failed',
  updatedAt
}
```

`composeEditPrompt` / `boxText` / `describeInstructions`(`ImageFilterClient.tsx:595-644`)는 입력 타입만 바꾸면 로직을 그대로 재사용합니다. **백엔드 변경 0건입니다.**

> 구현 순서: 구조 리팩터를 먼저 완료해 기존 동작 동등성을 확인한 뒤, 체크박스 선택 전송·순서 변경을 올립니다.

### C-2. 전송 전 요약 (pre-flight)

전송 버튼 위에 상시 표시: **"지시 2건 · 대상 1곳 · 출력 640×480 JPEG · AI 호출 1회 · 약 5~10초"**

이 제품은 `ai_usage_budget` / `ai_tool_usage_log`로 토큰 예산을 관리합니다. 비용이 발생하는 행동 앞에 비용을 노출하는 것이 기본입니다. 배경 시안은 `스타일 N종 = 이미지 생성 N회`인데, 현재는 패널을 열어야만 그 경고가 보입니다(`AgentComposer.tsx:249-251`).

### C-3. 자동저장 + 세션 복구

모달 내 자동저장은 "세션 안에서"의 보호일 뿐입니다. 새로고침·뒤로가기까지 막아야 완성입니다.

- 지시 목록 + 출력 설정을 **debounce 500ms로 localStorage 저장** (키 `imageFilter:instructions:v1`, TTL 24h)
- 재방문 시 배너: **"이전에 쓰던 지시 3건이 있어요 — [불러오기] [버리기]"**
- **이미지는 저장하지 않습니다.** "이미지는 서버에 저장되지 않아요"(`AgentComposer.tsx:445`)라는 기존 약속과 일관되게 로컬에도 남기지 않습니다. 복구 시 "이미지만 다시 첨부해 주세요" 안내.
- ⚠️ **요소 id는 이미지마다 새로 매겨집니다.** `handleAttach`(`:169-178`)와 `handleAnalyze`(`:242-243`)가 의도적으로 초안을 버리는 이유입니다. 복구 시에는 **지시 텍스트만 살리고 대상은 "미지정"으로 되돌린 뒤 카드에 "대상을 다시 골라주세요"를 표시**하는 것이 안전합니다.
- 참고 선례: `lib/reportStorage.ts`(IndexedDB + `QuotaExceededError` 처리 + prune), `hooks/usePendingRows.ts`(미저장 편집 스테이징, 219줄)

### C-4. `busy` 분리 — 기다리는 동안 일할 수 있게

| 작업 중 | 잠겨야 하는 것 | 열려 있어야 하는 것 |
|---|---|---|
| 요소 분석 | 요소 패널, 이미지 교체 | **지시 작성·수정 모달**, 출력 설정 |
| 편집(전송) | 전송 버튼, 이미지 교체 | 지시 열람, 결과 열람 |
| 배경 시안 생성 | 배경 버튼, 이미지 교체 | 지시 작성 |

"이미지 교체 금지"는 반드시 유지해야 합니다 — `latestFileRef`(`:132-136`)로 늦게 도착한 분석 결과를 버리는 방어가 이미 있는 이유입니다.

### C-5. 결과 비교 뷰 (before / after)

캔버스에 `[원본 | 결과]` 토글 + 드래그 슬라이더. 이미지 편집 도구에서 "제대로 바뀌었나"를 판단하는 유일한 수단인데, 현재는 320px 썸네일 두 개를 눈으로 왕복해야 합니다. 클릭 시 원본 해상도 라이트박스도 함께 제공합니다.

### C-6. 수동 박스 지정

AI가 요소를 못 찾으면(`elements.length === 0`) 현재는 전체 편집밖에 길이 없습니다(`AgentComposer.tsx:177-181`). **캔버스에 드래그로 직접 박스를 그려 대상을 지정**하게 하면, `boxText()`가 0~1 비율 좌표만 쓰므로 **백엔드·프롬프트 변경 0건**으로 커버됩니다. 투입 대비 효용이 가장 큰 항목입니다.

### C-7. 컨텍스트 기반 예시 지시

현재 `EXAMPLE_PROMPTS` 6개는 하드코딩이고 빈 화면에서만 보입니다(`ImageFilterClient.tsx:35-42`). 요소의 `category`(text / logo / product / person / background / graphic / other)별로 모달 안에서 다른 예시를 제안해 "뭐라고 써야 하지"를 줄입니다. 이후 **자주 쓰는 지시 저장(내 프리셋)** 으로 확장합니다.

### 구현 중 발견해 함께 고친 것

1. **전체를 덮는 요소가 다른 박스의 클릭을 가로채던 문제** — 서버는 이미지 전체를 덮는 "배경"(`category: background`, box 0,0,1,1) 요소를 흔히 돌려주는데, 그게 나중에 그려져 문구·로고 박스를 전부 가렸습니다. 넓은 박스부터 그려 아래에 깔도록 `ElementOverlay` 에서 면적 내림차순 정렬합니다.
2. **`Modal` 의 초기 포커스가 본문이 아니라 닫기 버튼으로 가던 문제** — 헤더도 포커스 트랩 안이라 첫 focusable 이 X 버튼이었습니다. `initialFocusRef` 를 추가해 모달을 열면 바로 입력칸에 들어갑니다.
3. **ResizeObserver 첫 통지가 안 오면 요소 박스가 영원히 안 그려지던 문제** — 캔버스 크기 측정을 ResizeObserver 에만 맡겼는데, 탭이 가려져 있거나 렌더러가 통지를 조절하는 환경에서는 **첫 통지조차 오지 않습니다**. 실제로 검증 중에 재현됐습니다 — 패널에는 "5개 찾음"이라 떠 있는데 이미지 위에는 박스가 하나도 없는 상태였습니다. 첫 측정은 ref 콜백에서 `getBoundingClientRect()` 로 직접 하고, ResizeObserver·window resize 는 이후 변화 추적용 보조 수단으로만 씁니다.

### localStorage 복구 (§C-3) — 구현 완료

`front/lib/imageFilterStorage.ts` (키 `imageFilter:draft:v1`, TTL 24h, debounce 500ms).

- **이미지는 저장하지 않습니다.** "이미지는 서버에 저장되지 않아요"라는 약속과 같은 이유이고, 수 MB 이미지를 localStorage 에 넣으면 쿼터가 금방 찹니다. 복구하면 이미지만 다시 첨부하면 됩니다.
- **요소를 지정했던 지시는 자동으로 되살리지 않습니다.** 요소 id 는 분석할 때마다 새로 매겨지므로 그대로 쓰면 엉뚱한 곳을 가리킵니다. 그렇다고 조용히 "이미지 전체"로 바꾸면 **"로고를 지워줘"가 이미지 전체 지시가 되어** 결과물이 완전히 달라집니다. 그래서 `needsTarget` 을 달아 **전송에서 빼 두고**(체크박스 비활성) 카드에 "대상을 다시 골라주세요 — 이전 대상: 브랜드 로고"를 띄웁니다. 모달에서 대상을 고르면("이미지 전체"를 고르는 것도 명시적 선택) 해제됩니다.
- 출력 설정은 **포맷·비율 고정만** 복구합니다. 가로·세로는 이미지에 종속된 값이라 다른 이미지에 되살리면 틀립니다.
- 읽기는 `useSyncExternalStore`(서버 스냅샷 `null`)로 합니다 — effect 로 읽으면 렌더가 한 번 더 돌고, 렌더 중에 읽으면 hydration 이 깨집니다.
- `새 작업`을 누르면 저장본도 함께 버립니다. 안 그러면 방금 치운 지시가 복구 배너로 다시 올라옵니다.
