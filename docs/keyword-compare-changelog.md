# 키워드 성과 비교 — 변경 이력

`keyword_compare_service.py` / `keyword_compare_router.py`(및 관련 프론트) 변경 사항을 시간순으로 누적한다.
새 변경이 생기면 파일 맨 위(최신순)에 새 항목을 추가한다.

---

## 2026-07-21 (2) — 헤더 라벨 정규화 + 진단 메시지(skipped_sheets) 추가

**배경**: 아래 (1)번 변경 직후, "이 감지 로직을 더 유연하게 바꾸면 어떤 장단점이 있는지" 검토하다가
- 헤더 라벨(`캠페인유형`)이 완전히 정확히 일치해야만 인식되어, 공백 하나만 달라도(`캠페인 유형`) 시트가 조용히 스킵되는 걸 재현 확인
- 원시 단일기간 시트 중 제목에서 날짜를 못 읽은 게 있으면 `date.min` 취급으로 정렬해, 최악의 경우 이번/저번 순서가 뒤바뀌어 증감 부호가 반대로 나올 수 있는 위험을 확인

**변경 내용**:
- `_header_offset`: 라벨 비교 전 공백류를 전부 제거하고 비교 (`캠페인 유형`, `캠페인유형 ` 등을 흡수). 라벨 자체가 다른 시트는 여전히 걸러냄 — 오탐 방지를 위해 유사도/부분일치까지는 넓히지 않음.
- 날짜를 못 읽은 원시 기간 시트는 `date.min`으로 추정해 끼워넣지 않고 **비교 대상에서 제외**함 (순서를 확신할 수 없는 데이터로 조용히 틀린 비교를 만드는 것 방지).
- `KeywordCompareService.parse_file()` 반환 타입을 `list[dict]` → `{"sheets": [...], "skipped": [{"name", "reason"}, ...]}`로 변경. 어떤 시트가 왜 제외됐는지 항상 기록.
- 라우터 `/api/keyword-compare/parse`: 정상 응답에 `skipped_sheets` 필드 추가, 결과가 0건일 때 422 `detail`에 어떤 시트가 왜 스킵됐는지 이유를 붙여 반환 (다음에 비슷한 파일 문제가 생기면 파일을 직접 열어보지 않고도 원인 파악 가능).

**검토했지만 보류한 것**: 컬럼 수(`available_cols >= 10 / >= 6`) 기준을 헤더 텍스트 기반 포맷 판별로 바꾸는 안 — 아직 이 경계값 때문에 실패한 실제 파일 사례가 없어 선제적 일반화로 보고 보류. 실제로 컬럼 수가 어긋나는 변형 파일이 나오면 그때 재검토.

**파일**: `back/app/services/keyword_compare_service.py`, `back/app/routers/keyword_compare_router.py`

## 2026-07-21 (1) — 원시 단일기간 시트 포맷 지원 추가

**배경**: 의뢰자가 업로드한 `work/엑셀1.xlsx`가 화면에 전혀 표시되지 않는다는 문의.
확인 결과 이 파일은 기존에 지원하던 "이번/저번 기간 비교가 이미 한 시트에 합쳐진" 포맷(비교 컬럼 10개, `back/example/키워드 비교 이번주저번주.xlsx` 참고)이 아니라,
**시트 하나당 한 기간(한 주)만 담긴 원시 데이터**(캠페인유형/기기/키워드/전환유형/전환수/전환매출액, 6개 컬럼) 2개 시트로 구성되어 있었음.
기존 파서는 컬럼 11개 미만 시트를 전부 스킵해 모든 시트가 걸러지고 "분석 가능한 시트가 없습니다" 오류가 발생.

**변경 내용**:
- 헤더 행에서 `캠페인유형` 라벨 위치로 포맷(오프셋 0/1)을 자동 판별하는 `_header_offset` 추가.
- 컬럼 수로 포맷을 두 갈래로 분기: `available_cols >= 10` → 기존 병합 포맷(`_parse_merged_sheet`), `>= 6` → 신규 원시 단일기간 포맷(`_parse_raw_period_sheet`).
- 원시 단일기간 시트가 여러 개 감지되면, 제목의 날짜 범위를 파싱해(`_period_end_date`) 종료일 기준 정렬 후 인접한 기간끼리 키(`campaign_type, device, keyword, conv_type`) 매칭으로 직접 증감 계산(`_compare_periods`).
- 기존 병합 포맷 파일(`키워드 비교 이번주저번주.xlsx`)은 동일하게 계속 동작 확인(회귀 없음).

**파일**: `back/app/services/keyword_compare_service.py` (신규 함수 다수 추가/리팩터링)

**참고**: `docs/keyword-compare-option1.md`에 이미 "원본 파일 2개 업로드 → 자동 비교"라는 유사한 구상(Option 1)이 있었음. 이번 변경은 파일 2개 업로드 대신 **한 파일 안의 시트 2개**로 같은 효과를 낸 것 — Option 1 자체(2파일 업로드 UI)는 아직 미구현 상태.
